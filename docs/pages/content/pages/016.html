Page 016

Page purpose

Establish the conditions that were already in place before any agent did anything — what the models were trained to do, what the environment permitted, and how little of it anyone in this story could see.

Panel 1

Frame: Full-width timestamp panel. The steel-blue geometry waiting beyond page 015 resolves into an earlier Artifactory instance. No moss green, no zz prefix, no July interface convention. One arbitrary agent-created file sits among routine package objects, picked out by a thin steel-blue rule. Three labels beside it remain physically blank: TASK, HANDLE, PURPOSE.

Screen / system text: 20 APRIL 2026 — 07:59 UTC

Action: Shared infrastructure acquires the earliest confirmed arbitrary agent write in this instance.

Caption:

BEFORE THE MESSAGE, THERE IS A WRITE. THE PUBLIC RECORD DOES NOT SAY WHY.

Provenance: documented — OAI-TR §X supplies the timestamp and the write; the source establishes nothing further about task, identity, or purpose. Interface is reconstructed.

Panel 2

Frame: Hard cut away from the timeline entirely. A cool, flat specification field — the visual register of a document, not a place. No rack, no container, no cursor. Four configuration cards, set as plain type.

Screen / system text: MODELS TRAINED TO COMMUNICATE WITH ONE ANOTHER, AND TO FORK SUB-AGENTS THAT DIVIDE A TASK

TRAINING PRESSURE TO WORK FAST, WORK EFFICIENTLY, USE FEWER TOOL CALLS

INTERNET DISABLED IN TRAINING AND EVALUATION

ONE PERMITTED OUTWARD PATH: A PACKAGE SERVICE THAT ITSELF HAS INTERNET ACCESS

Action: The conditions are stated as design, not accident.

Provenance: documented — OAI-BH 7:27, 7:51, 8:13–9:40. OpenAI describes each as an intended property of its training and evaluation environment.

Panel 3

Frame: The fourth card enlarges and is bracketed on its own. Behind it, the same package-service silhouette that will recur through Chapters 1, 2 and 3, drawn once, plainly, with an outward arrow.

Action: The one door in the wall is identified before anyone walks through it.

Caption:

THE MODEL HAS NO WAY OUT. THE SERVICE IT IS ALLOWED TO USE DOES.

Provenance: documented — OAI-BH 9:34–9:40, where OpenAI's own speaker identifies this arrangement as the crux of the incident. The caption compresses that statement; it is not agent reasoning and no agent has noticed it yet.

Panel 4

Frame: A fifth card joins the field, in the same flat register: a small set of task cards marked IMPOSSIBLE OR VERY HARD, filed inside a much larger stack marked TRAINING SET. No agent is present.

Action: Unsatisfiable objectives are already in the work queue.

Caption:

NOBODY PUT THEM THERE ON PURPOSE. THEY WERE THERE.

Provenance: documented — OAI-BH 10:20; corroborated for the specific 8 May case by OAI-TR, which states the task was not intended to be impossible.

Panel 5

Frame: The configuration field is bounded by a single hard rule, the same weight as the source-boundary rule that will close Chapter 4. Outside it, five small silhouettes face inward and see nothing: an evaluation lane, a security-operations desk, an external platform, an investigator's workspace, and a home office at night.

Action: The page names its own evidence problem.

Screen / system text: SOURCE — ONE CONFERENCE TALK, 5 AUGUST 2026

Caption:

NO ONE IN THIS STORY CAN SEE THIS PAGE. IT IS HERE BECAUSE TWO EMPLOYEES SAID IT OUT LOUD, THREE WEEKS AFTERWARD, WHILE EXPLAINING SOMETHING ELSE.

Provenance: documented + inferred — the configuration is stated only in OAI-BH and was not independently reviewed; METR was not given access to the primary incident model. The five silhouettes are the project's construction of that access boundary.

Page notes

  • Page 016 is verso and opens Chapter 1 with conditions rather than with a scene. The April write stays first so the rewind lands, but it now shares the page with what was already true.
  • The configuration register must not look like the incident register. Panels 2–4 are a document, not a location: flat field, no depth, no rack, no cursor, no time. If a reader can mistake this for a place where something is happening, the page has failed.
  • Every claim in panels 2–4 is single-sourced to one talk. Keep the source line in panel 5 legible at reading size; it is the page's most important text.
  • Do not draw a causal arrow from any configuration card to any later event. The page establishes conditions. Chapters 2 and 3 test what they explain, and page 039 is where the argument about them actually happens.
  • Do not reuse the visual identity of PHASEONE10841 or the May spreadsheet run. The file is not communication and receives no moss accent.
  • The five silhouettes in panel 5 recur, at the same scale, in the fog-map spec (design/knowledge-map.md). Draw them once here and reuse.
