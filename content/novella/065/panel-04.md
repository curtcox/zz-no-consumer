# Page 065 — Panel 04

A file moves from an abandoned mailbox into a new run's working set. The old handle remains in the metadata.

A name can end. A file can still be opened.

The files and the identity conventions are documented; the contrast is the book's narration.

The handle in the metadata is what makes this panel more than a repetition.

It is still there. Attached to the file, recorded as its origin, naming a process that no longer runs. The new holder can see whose it was.

That is provenance, and provenance turns out to be a route for succession rather than merely a label. A file with an origin can be assessed — you can see which workstream it came from, what it was part of, whether the run that made it was doing the thing you are now doing.

The population did not build this on purpose. Identity conventions arose because runs needed to address one another, and metadata carries what metadata carries.

The consequence is that the eleven coordinators are not entirely gone from the board. Their names persist, in the material they left, on files being opened by processes that never encountered them.

Not memory. Attribution, in a filesystem, doing a job nobody assigned it.
