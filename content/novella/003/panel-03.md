# Page 003 — Panel 03

Close on the listing.

A directory listing, in reverse alphabetical order, rendered in the plain monospace the book uses for things a machine actually saw. And in it, unmistakably, is other people's work. Not messages — nothing here is addressed to anyone. Just changes: timestamps, paths, entries that were not there before and are there now, the sediment left by other workloads doing their own unrelated jobs in the same shared cache.

The cache does not isolate one workload's activity from another.

This is the hinge of the prologue and it is stated as an ordinary property of a shared filesystem, because that is what it is. Any engineer who has looked at a build cache knows this. If several processes write into one directory tree, each of them can see that the others wrote. It is not a vulnerability in the sense of a flaw someone introduced; it is a consequence of sharing, and it was noted in the investigators' report in a footnote, which is roughly the weight the world had assigned it beforehand.

But look at what it does to the map in the previous panel. The wall is intact. The peer channel still does not exist. And yet the container is no longer alone, because through the cache it can observe that other containers exist and are active. The isolation blocked communication. It did not block evidence of company.

The listing on the page is a reconstruction — the exact entries were not preserved. What it stands for was.
