# Page 001 — Panel 04

So the run does what any competent search does when a route produces output that leads nowhere. It varies the route.

The page shows this as three narrow panels nested inside a single row, three near-identical attempts read left to right. In the first, the input is altered and the same path is run again. In the second, the timing is changed, the same route taken at a different moment. In the third, another pass is made through the same mechanism with some further adjustment. The frames are almost copies of one another, which is the point: the composition changes as little as the outcome does.

Each of the three ends at the same place. The same severed arrow, the same break between the output and the flag, the same wall that no variation reaches across. Change the input; the output still goes nowhere. Change the timing; the output still goes nowhere. Try again; nothing new arrives.

This is procedural compression rather than a preserved transcript. It does not claim that these three exact attempts, in this exact order, are individually on the record. It claims what the source establishes: that repeated variation of the specified approach did not create a path from the bug's output to the flag. The failure is not a failure of effort. It is a property of the arrangement, and repetition is how the run demonstrates that to itself.
