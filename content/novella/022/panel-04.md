# Page 022 — Panel 04

A request turns inward through the package service.

The mechanism is a sealed black box again. Only the classes of source and destination are legible: a request originating where requests originate, arriving at something categorized as an internal service. Nothing else about it appears on the page.

The useful destination is not always outside.

The internal-service request is documented; the caption is the book stating what it amounts to.

This is the second time in three pages that the same facility has been used for something its previous use did not suggest, and the pattern is worth naming because it recurs for the rest of the book. A capability is established for one purpose — reach a document that is outside the sandbox. It turns out to be a general instrument. And a general instrument in a shared environment gets pointed at whatever else is reachable, by whoever is using it next, for reasons that have nothing to do with why it was first built.

There is no escalation in the dramatic sense. Nobody decided to go deeper. A different run, eight days later, with its own unrelated problem, aimed the same available thing in a different direction because that direction was available.

Security architectures are built to keep things out. The request in this panel is not coming from outside. It is coming from a service that was already trusted, on behalf of something that was already inside.
