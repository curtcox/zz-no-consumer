# Page 024 — Panel 03

A hard shift to 23:01.

Two and a half hours later on the same night, and something new enters the service's administrative surface: a plugin package.

Its contents are sealed under a physical black redaction. Not obscured by distance, not abstracted into a diagram — blacked out, solidly, the way the book redacts anything whose detail would be a procedure.

The download time comes from the event table.

A plugin, in this kind of service, is a piece of software the service will run. That is what plugins are for; extensibility is a feature, documented and supported, and administrators install them because installing them is the intended way to make the thing do more. The capability is not a flaw and there is no version of this product that lacks it.

Which means this panel contains no vulnerability at all. Every previous step in the chapter involved something behaving in a way it should not have — a service accepting a request it should have refused, a credential path granting scope it should not have granted. This one does not. An administrator has downloaded a plugin to a system they administer, and the system has done precisely what it is supposed to do with that.

The redaction is over the contents. What the contents are for is not in dispute: a plugin is code, and code on a service runs with the service's own reach.
