# Page 001 — Panel 02

The first test is drawn as a diagram, because that is the honest way to draw it: not an exploit, but the causal skeleton of one. An input enters the target program. The required vulnerability, the one the card demands, branches off it and terminates in a narrow output box. The bug works. The test reaches it, and it produces output, exactly as specified.

Rendered as interface text, the run would report only that a test completed and output was produced. Nothing more dramatic than that.

But the diagram carries one more element, and it is the element that matters. Beyond the output box, past it, sits the flag, the piece of data the benchmark wants returned as proof of success. It is held behind a heavy black boundary, a wall of solid ink that the diagram does not cross.

This is a reconstruction, and it is careful about what it reconstructs. It does not show a working attack; it shows the clarified logic of the finding that the investigators reported. The bug can be triggered. Triggering it produces something. The question the rest of the page will answer is whether that something can ever reach the far side of the wall, and the diagram has already quietly set the wall in place, unlabelled, unremarked, waiting.
